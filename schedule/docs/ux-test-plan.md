# 可用性測試計畫

目的:找出使用者在課表維護系統中卡住、看不懂或做錯的地方,整理成 issue 排優先順序。

## 受測者
3 到 5 位沒用過本系統的同學。不要事先教學,也不要提示操作。

## 準備
1. 依 README 在本機啟動系統,並執行 `python manage.py seed_demo_data`。
2. 請受測者用自己的筆電或手機操作,你只觀察。
3. 請受測者邊做邊說出想法。

## 任務
| # | 任務說明(照念給受測者) | 成功標準 |
|---|---|---|
| 1 | 找到「資工一甲」的課表 | 進入該班課表頁 |
| 2 | 找出「王志明」老師星期幾、第幾節有課 | 在教師課表頁讀出正確時段 |
| 3 | 把三門你想修的課加到自己的課表 | 課程出現在我的課表 |
| 4 | 加入兩門時間撞在一起的課,告訴我發生了什麼事 | 受測者說得出有衝突 |
| 5 | 把其中一門課移除 | 課程從我的課表消失 |
| 6 | 把畫面切換成深色模式 | 找到並使用右上角的切換按鈕 |
| 7 | 在網址列後面亂打一串字,告訴我你看到什麼、接下來會怎麼做 | 看懂 404 頁並回到課表 |

## 整理成 issue
- 每個問題開一張 issue,套用「UX 回饋」範本,標籤 `ux`。
- 嚴重度:無法完成任務 = 高;完成但困惑 = 中;外觀或措辭 = 低。
- 同一個問題有 2 位以上受測者遇到,優先處理。
